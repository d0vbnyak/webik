# Чат-бот на сайте

Демо «AI-чат» на странице «Возможности» (`/capabilities`) отвечает настоящей
моделью, а не заготовленными фразами.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `server/kb.ts` | База знаний и системный промпт. Единственный источник фактов для бота. |
| `server/chat.ts` | Обработчик `/api/chat`: проверка запроса, лимиты, вызов модели. |
| `vite.config.ts` | Подключает обработчик к dev-серверу. |
| `src/components/demos/ChatBot.tsx` | Виджет чата. |

Модель — `claude-sonnet-5`, `effort: medium`. База знаний кэшируется
(`cache_control: ephemeral`): чтение из кэша стоит 0.1 от обычного входа,
запись — 1.25. Кэш живёт 5 минут с последнего обращения, так что экономия
появляется только при плотном потоке. На демо-сайте с редкими заходами запись
будет случаться чаще чтения, то есть каждый ответ выйдет чуть дороже, а не
дешевле.

## Ключ

`ANTHROPIC_API_KEY` в `.env`, **без префикса `VITE_`**. Vite вшивает в
собранный фронтенд только переменные с этим префиксом, поэтому ключ остаётся
на сервере. Проверить после сборки: `grep -r "sk-ant" dist/` — пусто.

`.env` в репозиторий не коммитится (`.gitignore`).

Без ключа эндпоинт отвечает 503 с внятным текстом, а не падает.

## Границы применимости

- **Работает только в `npm run dev`.** Обработчик живёт в dev-сервере Vite.
  Результат `npm run build` — статика, сервера у неё нет.
- **Для продакшена нужен Supabase Edge Function.** Логика из `server/chat.ts`
  переносится почти дословно, меняется обёртка `req`/`res` на `Request`/
  `Response`, ключ кладётся в секреты Supabase, а в `ChatBot.tsx` константа
  `CHAT_ENDPOINT` меняется на адрес функции.
- **История диалогов и счётчики лимитов живут в памяти процесса** и
  обнуляются при перезапуске. Для продакшена их надо перенести в таблицу
  Supabase, иначе несколько экземпляров функции не увидят ни лимиты, ни
  историю друг друга.
- **Лимит считается по адресу сокета.** За реальным прокси адрес посетителя
  придёт в `X-Forwarded-For`, но доверять этому заголовку можно, только если
  запрос точно пришёл от своего прокси — иначе лимит обходится подделкой.
- **Бот называет цены из прайса** — те же, что на странице `/prices`, всегда
  со словом «от». Единственный источник цен — `shared/prices.json`: оттуда
  читают и страница, и база знаний бота. Правится только он.
  `docs/прайс.md` — не копия, а обоснование: откуда взялась каждая цифра и по
  каким источникам рынка. Меняешь цену в JSON — обнови и обоснование.
- **Заявки никуда не уходят.** Бот просит почту, но не сохраняет её. Чтобы
  собирать лиды, нужна запись в таблицу Supabase.

## Лимиты расходов

Заданы в `server/chat.ts`, константа `LIMITS`:

- 15 сообщений с одного адреса за 10 минут;
- 300 запросов в сутки на весь сайт;
- 1000 символов на сообщение, 20 сообщений истории (`shared/chat.ts`);
- сессия живёт 30 минут без сообщений, в памяти не больше 500 сессий.

Публичный чат без потолка — открытый кран, за который платит владелец сайта.

## Если правишь сайт

База знаний в `kb.ts` не обновляется сама. Поменял услуги, команду или
контакты на страницах — поправь и её, иначе бот будет рассказывать клиентам
устаревшее.
