# Плагин webik → админка: синхронизация этапов

С 19.10.2026 админка ведёт проекты редизайна. Этапы — те же, что `stage` в
`.webik/state.json` плагина: `audited` → `designing` → `built` → `demo`, плюс
`prod` (выкладка на прод, ставится в админке вручную).

## Токен

Админка → «Настройки» → «Плагин webik» → «Выпустить токен». Токен виден один
раз; в базе хранится только SHA-256. Новый токен заменяет старый. Админка сразу
показывает фрагмент для `~/.webik/config.json`:

```json
{
  "admin": { "url": "https://webik.tech", "token": "<токен>" }
}
```

## Запрос

После каждого этапа, где плагин пишет `state.json`, он отправляет этот файл:

```bash
curl -sS -X POST "$URL/api/webik/projects" \
  -H "Authorization: Bearer $TOKEN" \
  -H "X-WebIK: 1" \
  -H "Content-Type: application/json" \
  --data @.webik/state.json
```

`X-WebIK: 1` обязателен для любого POST в API (защита от CSRF, см. `server/api/app.ts`).

Поля, которые принимаются (остальные игнорируются, `updated` в том числе):

| Поле | Обязательно | Что делает |
|---|---|---|
| `slug` | да | `[a-z0-9-]`, по нему ищется проект |
| `stage` | да | `audited`, `designing`, `built` или `demo` |
| `name` | нет | название при создании; дальше правится в админке |
| `source_url`, `design_artifact_url`, `demo_url` | нет | http(s); пустое значение не стирает уже записанное |

Ответ: `201` — проект создан, `200` — обновлён, тело `{ id, created, stage }`.
`401` — нет или неверный токен, `400` — текст ошибки в `error`.

## Правила

- Смена этапа пишется в журнал проекта («Плагин: Макет → Сборка»).
- Проект на этапе «Прод» плагин назад не откатывает: повторная выкладка демо
  после релиза — не возврат в работу. Ссылки при этом обновляются.
- Название задаётся только при создании; без `name` — домен старого сайта.
- Проект, заведённый в админке вручную (например, из заявки с сайта), плагин
  подхватит по совпадающему slug — slug в форме подставляется по тому же
  правилу, что в плагине (первая часть домена).

## Что нужно сделать в плагине

Отдельная задача в репозитории `d0vbnyak/webik-plugin`: после записи
`state.json` на каждом этапе — отправить его запросом выше, если в
`~/.webik/config.json` есть `admin`. Ошибка отправки не должна останавливать этап:
вывести предупреждение и продолжить.
