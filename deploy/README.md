# Деплой WebIK

Сайт и API админки — один контейнер `webik-app`, база — отдельный Postgres
`webik-db`. Всё живёт в `/opt/webik` на сервере второго бизнеса отдельным
compose-проектом `webik` и не трогает соседние контейнеры.

```
интернет → Caddy второго бизнеса (80/443, HTTPS) → webik-app:8080 → webik-db (внутренняя сеть)
```

## Выкладка

```bash
bash deploy/deploy.sh
```

Скрипт собирает всё локально (на сервере не тратится память на Vite), отправляет
на сервер и перезапускает только контейнеры WebIK.

## Первый запуск

1. `bash deploy/deploy.sh` — поднимет базу и приложение (сеть `webik_edge` из шага 4
   должна уже существовать — deploy.sh создаст её сам, если нет). Пароли базы сгенерируются
   на сервере в `/opt/webik/.env`.
2. Создать админа — в своём терминале, пароль вводите вы:
   ```bash
   ssh -t root@72.56.237.147 "cd /opt/webik && docker compose exec -it app node build/create-admin.mjs"
   ```
   Включите вход по коду из приложения — скрипт спросит.
3. Домен: A-запись домена WebIK → `72.56.237.147`.
4. Сеть: создаётся один раз, до первого деплоя, вне обоих compose-проектов, и
   Caddy второго бизнеса подключается к ней без перезапуска:
   ```bash
   docker network create --internal webik_edge
   docker network connect webik_edge sakhuslugi-caddy-1
   ```
   и, чтобы подключение пережило пересоздание контейнера, в
   `/opt/sakhuslugi/site/docker-compose.production.yml` у сервиса `caddy`
   добавить сеть `webik_edge` (внешнюю). Правку показать владельцу до применения.
5. Caddy: вставить блок из `Caddyfile.snippet` (с доменом) в
   `/opt/sakhuslugi/site/deploy/Caddyfile` и перезагрузить Caddy:
   ```bash
   docker exec sakhuslugi-caddy-1 caddy reload --config /etc/caddy/Caddyfile
   ```

## Что важно помнить

- **Caddyfile принадлежит второму бизнесу.** Папка не под git — если его деплой
  перезапишет файл, блок WebIK пропадёт и сайт перестанет открываться (второй
  бизнес при этом не пострадает). После деплоя второго бизнеса проверять.
- **Ни одного `ports:` в compose.** Docker обходит UFW: опубликованный порт виден
  из интернета мимо файрвола.
- **Чат на сайте в проде выключен.** Anthropic API не обслуживает Россию; вернётся
  с российской моделью.
- **Бэкап базы** (пока вручную). В дампе персональные данные — только в
  зашифрованном виде, пароль архива — в менеджере паролей:
  ```bash
  ssh root@72.56.237.147 "docker exec webik-db-1 pg_dump -U webik_admin webik | gzip" | 7z a -si -p webik-$(date +%F).sql.gz.7z
  ```
  Хранить не на этом сервере. Раз в месяц проверять, что дамп восстанавливается.
- **Ещё не сделано** (по аудиту, низкий приоритет): образы закреплены тегами, а не
  digest; TOTP-секрет в базе не зашифрован.
- **Журнал входов** — таблица `login_events` (время, адрес, итог; без паролей).
